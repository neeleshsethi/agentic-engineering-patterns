A deep run is not just a model loop. It is a checkpointed state machine where each field has a merge rule, a lifetime, and a failure mode.

The package map

Four groups explain most of agent/deep/

Control flowgraph.py, gate.py, plan.py
The graph assembles the agent; the gate owns approval; the plan module converts todos into a typed plan.
MiddlewareContext, manifest, sufficiency, budget, exit
These wrap model calls, tool calls, and exit behavior. Their order is part of the contract.
Executionanalyst.py, interpreter.py
Long-running analysis happens in a bounded code loop, outside the quick answer path.
Worker plumbingSQS, run state, locks, resume claims
Approval is durable, queued, claimed, resumed, streamed, and completed by a worker.

Overrides

Other channels replace the old value

Planplan is sticky. Only submit_plan writes it, so stale-plan bugs are serious.
Cyclecycle is the turn-boundary counter. It feeds plan_id.
Proposal contextraw_question, user_context, language, and deep_run_id overwrite per proposal.
Exit outputsFinal answer, source cards, chart anchors, and reported_cycle are last-value outputs.

The approval decision is not just another state field. It is staged for resume, then consumed by the worker path.

Turn classifier

The full plan workflow runs only twice

Turn typePlans?What happens
First questionYeswrite_todos to submit_plan to approval gate.
New topic follow-upYesFresh cycle and fresh plan_id.
Entity or metric gapNoAsk one terminal clarification before planning.
Mid-retrieval elicitation replyNoSame locked plan; re-query only the open step.
ExtensionNoRetrieve directly under the current locked plan.
Evidence reply or presentation changeNoAnswer from held evidence or rebuild artifacts once.

The invariant

A submitted plan is fully determined

1
Clarify before planning. If there is no safe default for an entity or metric, ask before todos exist.
2
Approve exactly once. Plan-gate source ambiguity can ride the approval card, but approval is still the lock point.
3
Keep locked plans locked. Extensions and elicitation replies should not mint a new plan_id.

Remember

State design is failure design

Use accumulating reducers for evidence, messages, and parallel branch bookkeeping.
Use last-value channels for proposal context and final report outputs.
Only new questions should reopen the plan workflow. A locked plan keeps carried evidence attached to the current cycle.
