Reuse the answer, not the megabytes

A Cortex call returns a prose answer and a data table that can be a thousand rows. You want the model to reuse a prior turn's answer instead of re-querying — but you cannot paste a thousand rows back into the window every turn. So you inject an index of metadata, never the data.

The problem

Two ways to lose, and the manifest avoids both

Re-query what you holdThe answer is already in state["source_results"]. Re-querying Cortex is slow, costly, and sometimes non-deterministic — wasteful when you already have the answer.
Paste the data backAvoid re-querying by re-injecting the rows and you poison the window: a thousand stale rows bury the conversation, blow the token budget, and degrade attention.

The fix is to give the model an index of what it holds — shape and age in ~100 bytes — and let it decide reuse-versus-refetch itself.

Why ambient

Injected every turn, not a lookup tool

Ambient manifestRebuilt from state and framed onto the latest human message via wrap_model_call — transient, never checkpointed. The option to reuse is always in view.
A search_held_data toolCosts extra model turns and fails silently: when the model doesn't think to call it, it just re-queries and nothing flags the missed reuse.

"The model can only reuse what it knows it holds — and it can't ask about what it doesn't know exists." Capped at the newest 30 lines, newest-first; older ones roll into one honest line.

Keeping reuse honest

Two hard boundaries — the anti-poisoning guarantees

BoundaryRuleWhy
Prose-only reuseReuse a held answer's text, never its data rows. Need figures the prose doesn't state? Re-query — never estimate.The rows aren't in context, only the pointer is. rows=412 says data exists to re-pull, not that it's in the window.
Staleness checkEvery line carries retrieved. Prefer a fresh pull when held data looks stale; old rollups say "ask the user first."A follow-up asking for "current" numbers must not silently reuse a week-old table.

Reuse the conclusion a prior turn reached; re-fetch the evidence whenever the new answer depends on numbers you are not holding.

Visible at approval

Reuse is a plan step, not a hidden optimization

At plan time the orchestrator writes a step with no [source:] tag that names the held result by its provenance id, so a reviewer sees the reuse before approving.

Reuse step (no source tag)Reuse the sales already retrieved (SUBNATIONAL:plan-c1-1:step-1:a3f9c2d1) [group: 1 parallel]

Remember

Index over state, never a copy of it

Inject pointersProvenance id, shape, age — ~100 B/line. The moment a data row is in the block, you're poisoning the window.
Keep it ambientA reuse path the model must remember to look up is one it will silently skip.
Forbid estimationProse may be reused; numbers must be re-fetched. Carry the age so staleness is part of the decision.
