Production Deep Agent Engineering

Every fact needs a durable name

In a deep agent, retrieval can be parallel, retried, redelivered, and reused. Provenance is the naming scheme that keeps evidence from collapsing into a pile of similar-looking rows.

7 slidesIDsCitations1 quiz

Why provenance exists

A single-shot agent can use memory. A deep agent needs identity.

Async redeliverySQS can deliver the same work again. A stable evidence-set stamp lets the exit path no-op an already reported cycle.
Accumulating statesource_results spans turns. The current answer must filter by current plan_id, not by "everything in memory."
Parallel fan-outSeveral retrievals can finish in one graph step. Deterministic IDs make retry deduplication a string comparison.
Downstream joinsCitations, cards, chart series, and activity logs all need to point to the exact retrieval that produced a fact.

The keystone

provenance_id names one retrieval call

provenance_id = "{source}:{plan_id}:{step_id}:{sha1(sub_question)[:8]}"

# Example:
# cortex:plan-thread-123-2:step-1:a1b2c3d4

An identical retry intentionally gets the same ID. A changed clarification answer changes the sub-question hash, so the new retrieval gets a new ID.

Ordinals

There are three order numbers. Only two are join keys.

OrdinalCountsPurpose
retrieval_ordinalRetrievals in a reportMaps report markers like [3] back to source results.
source_ordinalRetrievals in a cycleCard/table join key so citations attach to the right retrieval.
card["ordinal"]Cards in display orderDisplay only. Not a citation join key.

The bug to avoid: joining citations to cards by display order. One retrieval can fan out to multiple cards, so display ordinal can diverge from retrieval ordinal.

Cycle stamps

Evidence-set identity blocks duplicate reports

cycle_stamp = {
    "plan_id": plan.plan_id,
    "provenance_ids": sorted({r.provenance_id for r in results}),
}
reported_cycleCompared for equality before writing a report. Same evidence set means redelivery is a no-op.
chart_cycleChart anchors join only against a same-cycle catalog, so stale charts cannot attach to a new report.

Remember

Use the narrowest stable name

source_id says where evidence came from. It does not say which retrieval it was.
provenance_id says exactly which retrieval produced the evidence.
deep_run_id resets per question; run_id resets per worker attempt.
A cycle stamp names the delivered evidence set, not just the current plan.
